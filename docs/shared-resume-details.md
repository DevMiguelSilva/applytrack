# Shared resume details

The CV library retains resolved CVs in `cvs` for existing matching, tailoring, and database guards. Contact, education, projects, and certifications are copied to each resolved CV when saved. `sharedDetails.roles` holds reusable role facts; each profile's experience list retains its own bullets and order. Saving a newly added role adds it to every other existing profile with empty highlights. Saving a role removal removes that role and its highlights from every profile that uses it. Existing roles are assigned distinct IDs at migration, even when their text matches, to avoid merging ambiguous records.

On first load, the Power Platform profile is identified by its legacy ID or a unique matching profile name. If it cannot be identified, loading stops. The original document is kept in `sharedDetails.original` for recovery; it is not exposed as a control in the CV editor. Local migration also stores the original under `applytrack-master-cv-before-shared-v1` before writing; a conflicting backup stops migration. Cloud migration first writes and verifies `sharedMigrationBackup` using the current revision, then conditionally writes the migrated document. A failed second write leaves that backup in the cloud document for retry. After a successful migration, the original is stored at `document.sharedDetails.original`; `document.sharedMigrationBackup` may also be present if migration stopped between its two writes. No database schema migration is required.

### Recover and reconcile pre-sharing details

Keep the recovery panel out of the CV editor. The original backup is available from the same browser or the user's cloud library:

- **Local storage:** Open the same ApplyTrack origin and browser profile used during migration. In browser DevTools, open **Application** (Chrome/Edge) or **Storage** (Firefox), choose **Local Storage**, select the ApplyTrack origin, and copy the value of `applytrack-master-cv-before-shared-v1`. Save it as a `.json` file. If that key is absent, copy `applytrack-master-cv`, parse the JSON, and save `sharedDetails.original` instead.
- **Cloud storage:** In the Supabase dashboard for the configured project, open **Table Editor → master_cvs**, locate the row whose `user_id` is your account ID, and inspect its `document` JSON. Copy `document.sharedDetails.original` to a `.json` file. If migration stopped between its backup and migrated-document writes, use `document.sharedMigrationBackup` instead. The table is protected by row-level policies for each user's own record; do not share the exported file or expose service credentials.
- **Reconcile:** Open the saved JSON and compare the old profiles' contact, education, projects, certifications, and other shared fields. Choose the values to keep, then update those sections in the current CV editor and save. Those sections now apply to every profile, so one chosen value becomes the shared value across profiles. Do not replace the current library with the whole old document: that would roll back newer profile changes and metadata. Keep the backup until reconciliation is complete.

The editor warns which sections affect all profiles, provides move controls for each list, and stages imports for review before saving. On explicit import save, added and removed roles affect all profiles; removed roles lose their profile-specific highlights. Library revision checks reject stale drafts, and import results are discarded after an account or library change. The backup may contain personal resume data and should be handled accordingly. Do not open an older application version against a migrated library: older versions do not understand the shared metadata and could discard it. Submitted documents continue to use their stored snapshots.
